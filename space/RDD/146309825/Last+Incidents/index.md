# Last Incidents

## Overview

When an alert matches the defined conditions in an incident rule, an incident is created. Users can also create incidents from two or more existing alerts when they are related. In any case, a quick notification to all the involved stakeholders is key. Dashboards are useful assets due to their ability to combine information from different sources, for example, some users combine in the same dashboard panel this gadget together with the [Last Failed Pipeline](/cms_trial/space/RDD/146309787/Last+Failed+Pipeline/) or [Deployments](/cms_trial/space/RDD/146309688/Deployments/) gadgets. Easing the rapid response to emergencies.

**Alert**: Information about an event or occurrence that warrants attention <https://roninpixels.atlassian.net/wiki/pages/resumedraft.action?draftId=122486938>

**Incident**: Major incident, an event that causes disruption to or a reduction in the quality of a service which requires an emergency response

This gadget displays the last three incidents, the creation date, the tags and actions, the priority, status, and the responder teams involved in the incidents.

## Configuration

Name your gadget meaningfully, so everyone knows at a glance what it is about and when to use it. Fill out the rest of the fields as applicable, namely:

- The **datasource**, select an Opsgenie datasource (see [Add and manage datasources](/cms_trial/space/RDD/146309293/Add+and+manage+datasources/)).
- Finally, indicate if you want to use the current settings for all the compatible gadgets in the dashboard. This option eases the pain of configuring one by one the rest of the gadgets with the same default configuration.
