# Heatmap mode (Goals)

## Heatmap mode - Goals module (old navigation)

Click to expand the guide

You can color-code the goals displayed when the Heatmap mode is enabled.

Use color coding in different ways, one of which is monitoring ongoing goals' health status. For example, the Release Train Engineer can better keep track of goal completion during Scrum of Scrums meetings.

Click the **View** button in the top menu to open the available options:

- None
- By status
- Manually

![image-20260508-102505.png](/cms_trial/assets/40183570-d8b7-4467-89ca-dd367ba860d1.png)

## Heatmap mode (options)

### None

Heatmap mode is off.

### By status

There are three default colors used in this mode, which change together with goal status changes:

- **Completed** (green)
- **Abandoned** (grey)
- **Failed** (red)

An goal will not be highlighted when it is in the Open status.

![Main Objectives, two objectives highlighted](/cms_trial/assets/faa173e6-2bd2-47eb-b719-4fdf3b5cae2c.png)

## Manually

Heatmap mode is set to **Manually,** and lets you edit colors associated with individual goals. You can change the colors manually by editing the goal. To open the "Details dialog," double-click on the goal or right-click and select Details.

The health status can be presented following the traffic light convention:

- Green
- Yellow
- Red

Each health status can have a description defining its meaning. For example, green indicates being on track, yellow indicates being at risk, and red indicates being off track.

![Details, position and path highlighted](/cms_trial/assets/30074e08-52c4-4b32-b527-f0c829254fc9.png)

### Colors configuration

Settings are applicable only in a manual heatmap mode.

Settings are changed per Box type.

App admins can define the colors for each Box type in App administration > [Box types](/cms_trial/space/SPM/1918830000/Box+types/) > Select the box type to edit > Goals > Colors.
