## Enhencements

## Workload and capacity

### Skill capacity distribution isn’t assumed to be equal

If a resource has multiple skills assigned, the app doesn’t assume equal distribution of capacity across those skills.

For example, if a developer has both frontend and backend skills assigned, 100% of his time counts as potential backend and frontend capacity.

![image-20260407-035706.png](/cms_trial/assets/9d5dd669-ced1-42b2-ad6c-8849988cb36d.png)

If they have remaining capacity left, all of it counts as potential frontend and backend developer capacity. The app doesn’t assume the time will be equally divided across skills.

![image-20260407-035833.png](/cms_trial/assets/deb21646-12e5-4e00-8f29-ff0ad114ac67.png)

## Task status change

### When additional fields are required to change the task status, the task details window opens

If no extra fields are required, the status can be changed in BigPicture as usual. If any extra fields are required, Jira work item modal opens, letting you fill out the necessary information.

## New homepage

### The project health report (RAG report) is available on the homepage

The new project health (RAG) report gives you a clear, visual overview of project status using the classic Red–Amber–Green system. The status is derived from three key indicators: progress burndown, capacity vs. workload, and high-severity risks.

The color-status thresholds for each indicator can be customized by a Jira Admin.

![image-20260309-130533.png](/cms_trial/assets/82b564b8-7d80-4513-82c1-cdd760bd3618.png)

## New navigation

### When filtering for favorite boxes, you see the greyed out parent it the box tree

When enabled, the favorites filter shows only starred boxes:

- with their parents as greyed out rows
- the child boxes which are not starred are hidden
