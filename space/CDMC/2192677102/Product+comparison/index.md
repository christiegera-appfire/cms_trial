### Draft and published view navigation

 ✅ – Available | ❌ – Unavailable | ⚠️ – Partially available

| **Draft and published documents** | **Description** | **Data Center** | **Cloud** |
| --- | --- | --- | --- |
| **Draft and published views** | Users navigate between the work-in-progress version and the last approved version of a page   - final state - draft states   **View approved** byline added to draft states to support the user in navigating to the *last approved version*. This is the version created on the transition to the final state in the workflow. | ✅ | ✅ |
| **Draft state view restriction** | Default workflow visibility: Content in a draft work-in-progress state is not visible to users with only Confluence **view** permission for the page. View-only users are directed to the *last approved version* if it is available. | ✅ | ❌  The workflow does not differentiate user access between the work-in-progress versions and the page's last approved version. User permissions for a page are managed by using the Confluence user permissions.  The [copy-page trigger action](/cms_trial/space/CDMC/2193950590/copy-page/) in the cloud app is useful as a workaround to manage the visibility of the draft work-in-progress content. You use the trigger action to copy the latest approved final state version. User permissions can be managed separately on the copied page. The trigger can be set to copy the page to a location in the same space or another specified space. |
| In both the data center and the cloud, permission management can be implemented using a Comala workflow and the [Comala Publishing app](https://appfire.atlassian.net/wiki/spaces/CPCL/pages/614859157) to publish pages in a separate space with anonymous user permissions. |
