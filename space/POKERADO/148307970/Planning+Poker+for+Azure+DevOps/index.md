# Planning Poker for Azure DevOps

**Planning Poker for Azure DevOps** brings collaborative, consensus-based estimation directly into Azure DevOps. Your team estimates together without leaving your boards, with no spreadsheets and no separate tool, and final estimates save straight back to the work item.

Private voting keeps estimates honest. Everyone commits a card before anyone sees the others, so nobody just agrees with whoever spoke first. Live games work when the team is online together, and async mode lets distributed teams vote on their own schedule, with an optional comment on each vote to explain the reasoning.

## Common use cases

### Sprint planning and backlog refinement

[Run a game](https://support.appfire.com/space/POKERADO/3008299028/Get+started+with+Planning+Poker#Run-your-first-estimation-game-in-Planning-Poker) before each sprint so the team estimates the backlog together instead of one person guessing alone.

### Distributed and remote teams

[Async estimation](https://support.appfire.com/space/POKERADO/3560898577/Use+async+estimation+for+distributed+teams) lets each person vote on their own schedule instead of requiring everyone live at the same time. Useful when the team spans time zones or works non-overlapping hours.

### Large-scale and release planning

[Pull work from an Azure DevOps query](https://support.appfire.com/space/POKERADO/3315008376/Create+game#By-Query) into a single game to size a release or a program increment (PI) across multiple teams in one pass. Use spectators for stakeholders who want visibility without voting.

### Re-estimating carried-over work

[Quickly re-vote](https://support.appfire.com/space/POKERADO/3008299028/Get+started+with+Planning+Poker#Re-voting-and-re-estimating) on items that rolled over so estimates stay accurate as the team's understanding changes.
